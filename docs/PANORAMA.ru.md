# MapDecals 1.1.1: установка и проверка Panorama

## Результат проверки приложенных файлов

`swiftly_menu_ui.xml` и `swiftly_menu_ui.css` подходят как визуальная основа. В XML есть шесть слотов `utils-item-0`…`utils-item-5`, переключатели, кнопки назад/закрыть и пагинация. Переписывать дизайн или добавлять JavaScript для этого меню не потребовалось: сервер использует `CCSCustomHudLayout` и событие `OnCustomHudClicked` SwiftlyS2.

Предоставленные файлы — декомпилированные исходники Source 2 Viewer. Их наличие не означает, что они уже доступны клиентам, а корректный XML не гарантирует успешную компиляцию ресурсным компилятором CS2. В этой среде нет CS2 Workshop Tools, сервера и игрового клиента: компиляция ресурсов и работа в игре ещё не проверены.

Чтобы не менять меню админки, копии получили отдельные пути:

```text
panorama/layout/custom_game/mapdecals_menu_ui.xml
panorama/styles/custom_game/mapdecals_menu_ui.css
```

В XML изменена только ссылка на собственный CSS. Идентификаторы панелей и оформление сохранены. Несколько экземпляров layout принадлежат разным HUD-сущностям, поэтому сервер фильтрует клики также по сущности и владельцу.

## Требования

- SwiftlyS2 **1.5.0-beta.26 или совместимая более новая версия**; версия 1.1.1 собрана именно с пакетом 1.5.0-beta.26 и объявляет такой же MinimumAPIVersion. В предыдущей сборке 1.1.0 был указан минимум stable 1.5.0, который загрузчик beta.26 отклонял. Это исправление проверено компиляцией, а не запуском на сервере.
- .NET 10 для самостоятельной сборки.
- Существующее подключение БД `cc_mapdecals` в конфигурации SwiftlyS2.
- Cookies и поставляемый `Cookies.Contract.dll` для сохранения пользовательских предпочтений.
- Для Panorama: собственный Workshop-контент с скомпилированными UI-ресурсами, доступный **каждому клиенту**. Простого копирования XML/CSS в серверную папку plugins недостаточно.

## Серверная установка

1. Сделайте резервную копию БД и конфигурации. Схема `cc_mapdecals` сохранена; новая миграция данных не добавляется.
2. Остановите сервер либо выгрузите старый плагин.
3. Распакуйте `CS2-MapDecals.zip` в `game/csgo/addons/swiftlys2/plugins/CS2-MapDecals/`. Внутри этой папки должны находиться DLL и `resources/`, а не ещё один уровень `CS2-MapDecals/`.
4. Сохраните конфигурацию и подключение БД. Не заменяйте рабочие материалы демонстрационными.
5. Сначала запустите со старым меню: `MapDecals.UsePanoramaMenu = false` (значение по умолчанию).

## Подключение клиентских ресурсов

1. В своём addon-проекте **CS2 Workshop Tools** скопируйте два файла из `panorama/` репозитория в content-дерево с сохранением относительных путей.
2. Скомпилируйте XML и CSS инструментами CS2. Ссылка CSS в XML указывает на `s2r://panorama/styles/custom_game/mapdecals_menu_ui.vcss_c`.
3. Проверьте, что в game-выводе присутствуют скомпилированные layout/style ресурсы. Упакуйте их в используемый сервером Workshop-контент/карту и обновите публикацию.
4. Убедитесь, что клиент загрузил и смонтировал этот контент; протестируйте с клиентом без локальной копии исходников. Публикация или обновление только серверной DLL недостаточны.
5. В существующую секцию `MapDecals` файла `config.json` добавьте поля, не удаляя `Props` и команды:

```json
{
  "UsePanoramaMenu": true,
  "PanoramaLayout": "panorama/layout/custom_game/mapdecals_menu_ui.xml"
}
```

Это **поля внутри секции**, не полная конфигурация. В `PanoramaLayout` используется логический путь `.xml`, как в Custom HUD; CSS подключается самим layout.

6. Перезапустите сервер/смените карту после доставки ресурсов, затем вызовите `!mapdecal` с правом `cc-mapdecals.admin` (или своим настроенным правом).

Не перезаписывайте существующий `swiftly_menu_ui` админки: новые пути позволяют обновлять оба интерфейса независимо. Если нужен ровно прежний путь из уже опубликованного Workshop addon, его можно указать в `PanoramaLayout`, но это создаёт зависимость от версии админки и её UI-контракта.

## Управление

- `!mapdecalclose` (либо `sw_mapdecalclose` в клиентской консоли) принудительно закрывает собственный Panorama HUD и освобождает курсор, даже если layout не отрисовался.
- Главное меню: выбор материала / список декалей текущей карты.
- Список: по шесть пунктов, переход стрелками; название включает ID для различения одинаковых имён.
- Размещение: выберите материал; курсор освобождается, после чего поставьте обычный игровой пинг. `!cancel` отменяет ожидание пинга; повторное открытие команды также отменяет его.
- Редактор: включение, имя, координаты/углы, ширина/высота/глубина, принудительное отображение, удаление с отдельным подтверждением.
- Имя и числа вводятся **в чат**, а не в HTML/TextEntry. Ввод перехватывается и не отправляется в общий чат. На ввод есть 60 секунд; `!cancel` возвращает в меню. После истечения срока обычное сообщение снова идёт в чат. Другие команды с `!` или `/` не перехватываются как значение.
- Числа: точка как десятичный разделитель; `NaN`, бесконечности и выход за диапазон отклоняются. Координаты ±32768, углы ±360°, ширина/высота 1–4096, целочисленная глубина 1–256 (дробная часть глубины отбрасывается).
- Название: уникальное в текущем списке карты, 3–64 символа, без управляющих символов.
- Тексты: `en.jsonc`, `ru.jsonc`; язык выбирается штатной локализацией SwiftlyS2.

`ForceOnVIP` сохранён для совместимости БД: он игнорирует пользовательское отключение `!decal`, но **не обходит** `ShowPermission` материала. Если право материала не задано, он доступен всем. При `ForceOnVIP=false` видимость также зависит от сохранённого предпочтения игрока.

## Безопасность и жизненный цикл

- Клик принимается только от владельца активного HUD, с актуальным правом администратора и допустимым ID видимой строки.
- Есть ограничение частоты кликов и блокировка параллельного изменения одной декали через Panorama.
- При ошибке записи Panorama не применяет изменение в памяти; удаление выполняется только после успешной операции БД.
- Карта/выгрузка отменяют устаревшие UI-сессии; результат асинхронной загрузки другой карты не подменяет текущую.
- Курсор освобождается при закрытии, отключении игрока и выгрузке.
- Старое меню оставлено как совместимый fallback. Оно использует устаревший, но ещё доступный в 1.5.0 `MenusAPI`; предупреждения CS0618 подавлены только в файлах fallback. Новое Panorama-меню от этого API не зависит. Сериализация/проверка ошибок редактора усилены именно в Panorama; старое меню не получило полного transactional redesign.

## Проверки

```bash
dotnet restore src/CS2-MapDecals.csproj --locked-mode
dotnet restore tests/MapDecals.Tests/MapDecals.Tests.csproj --locked-mode
dotnet run --project tests/MapDecals.Tests -c Release --no-restore
dotnet publish src/CS2-MapDecals.csproj -c Release --no-restore
```

Ожидаемый ZIP: `artifacts/CS2-MapDecals.zip`. Тесты проверяют правила ввода, пагинацию, таблицу истинности видимости и настоящую SQLite-миграцию/CRUD. Эти тесты не эмулируют игровой движок и не проверяют сетевое отображение.

### Обязательный smoke test на тестовом сервере

- [ ] Чистый клиент получает Workshop-ресурсы, меню видно, клики доходят до сервера.
- [ ] Меню админки и MapDecals не конфликтуют; отдельно проверить открытие одного поверх другого: координация курсора между независимыми плагинами не реализована.
- [ ] Нет доступа без админ-права; отзыв права после открытия блокирует действие.
- [ ] 0, 1, 6, 7 и >12 материалов/декалей: корректная пагинация и переход назад.
- [ ] Размещение пингом, отмена, смерть до пинга, отключение игрока до сохранения.
- [ ] Положение/углы, размеры, переименование, отклонение некорректных чисел и повторяющихся имён.
- [ ] Оба ответа подтверждения удаления; отказ БД не удаляет декаль из памяти.
- [ ] Два администратора одновременно редактируют одну декаль.
- [ ] Смена карты во время загрузки/сохранения; hot reload; несколько рестартов раунда без дублей.
- [ ] Видимость проверена двумя клиентами: без `ShowPermission`, с правом, с/без `ForceOnVIP`, до/после `!decal`, после реконнекта и нового раунда.
- [ ] Отдельно MySQL/MariaDB и PostgreSQL: интеграционные тесты здесь проведены только для SQLite.

Если XML/CSS не компилируются из-за особенностей декомпиляции, необходимы оригинальные исходники или корректировка по сообщению Workshop Tools. Если HUD невидим, верните `UsePanoramaMenu=false` и проверьте пути, доставку контента и клиентскую консоль. Сервер не может надёжно определить, действительно ли конкретный клиент отрисовал ресурс, поэтому автоматическое переключение на fallback не обещается.
