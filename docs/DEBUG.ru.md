# Диагностика невидимых декалей — 1.1.3

Сборка рассчитана на SwiftlyS2 **1.5.0-beta.26 / .NET 10**. Она добавляет наблюдение, а не исправляет материал или способ проекции. Меню продолжает использовать `panorama/layout/custom_game/swiftly_menu_ui.xml`.

## Установка и воспроизведение

1. Остановите сервер, сохраните резервную копию плагина. Распакуйте новую папку `CS2-MapDecals` в `game/csgo/addons/swiftlys2/plugins/` с заменой файлов этой папки. Не создавайте вторую копию DLL под другим именем. Конфигурацию и БД удалять не нужно. Новая компиляция Panorama не нужна.
2. В существующем `config.json`, **внутри объекта `MapDecals`**, добавьте/измените только эти поля:

   ```json
   "DebugLogging": true,
   "DebugLogToFile": true,
   "DebugPlayerTransmit": true
   ```

   Это фрагмент JSON, не полный файл. Сохраните `Props`, команды, права, `UsePanoramaMenu` и `PanoramaLayout`; проверьте запятые между полями.
3. Запустите сервер и загрузите карту. Полный перезапуск даёт лог загрузки и события запросов precache; включение флагов на уже запущенной карте не повторяет precache.
4. Подключитесь, откройте `!mapdecal`, выберите свой материал, наведитесь на стену и поставьте метку пингом. Не удаляйте старые декали ради диагностики.
5. Выполните в игровом чате:

   ```text
   !mapdecaldebug 3
   ```

   `3` — пример ID из заголовка редактора. Для новой декали подставьте её ID. Команда без ID делает ограниченный снимок текущих записей.
6. Заберите `mapdecals-debug.log` с сервера. **Точный абсолютный путь команда выводит в ответе**; он также указан при загрузке плагина. По умолчанию это каталог данных плагина, обычно:

   ```text
   game/csgo/addons/swiftlys2/data/cc.mapdecals/logs/mapdecals-debug.log
   ```

   Все строки дублируются в обычный серверный лог с маркером `[MDDBG]`. При ошибке записи файла они остаются в консоли. Если файл пуст/не создан, проверьте `DebugLogToFile` и предупреждение о правах записи.
7. После воспроизведения верните `DebugLogging` и `DebugPlayerTransmit` в `false`: файловая запись синхронная и подробные логи не предназначены для постоянной работы на заполненном сервере. `DebugLogToFile` можно оставить `true` для ручных отчётов.

## Команды

| Где | Команда | Назначение |
| --- | --- | --- |
| Чат | `!mapdecaldebug 3` | Снимок одной декали и видимости для вызвавшего игрока |
| Чат | `!mapdecaldebug` | Снимок первых 32 записей текущей карты |
| Консоль клиента / сервера | `sw_mapdecaldebug 3` | Тот же отчёт; серверная консоль проверяет всех реальных игроков, до 128 пар игрок–сущность |
| Чат | `!mapdecaldebug paths` | Только сведения о сервере и смонтированных путях GAME |

Игроку нужны права администратора из `PlaceDecalCommands.Permission` (обычно `cc-mapdecals.admin`). Серверной консоли права игрока не нужны. Ограничение частоты — один отчёт в две секунды на слот/серверную консоль. Ручной отчёт работает и при `DebugLogging=false`; файл зависит от `DebugLogToFile`.

Команда **не меняет** сущности, позиции, разрешения, настройки игрока и монтирование контента. Она пишет только диагностический вывод/файлы логов.

## Что искать в логе

- `LOAD`, `CONFIG_PROP`: версия, активный режим меню, `UniqId`, материал, требуемое право просмотра.
- `PRECACHE_REQUEST`: путь был передан в `AddItem` во время события precache. Это **запрос**, не подтверждение успешной компиляции или загрузки клиентом.
- `MATERIAL_VFS`: поиск `materials/mapdecals/2.vmat_c` через **смонтированную файловую систему сервера `GAME`**, включая VPK, и размер найденного файла. `serverGameExists=False` — сервер сейчас не разрешает этот путь; проверьте установку, монтирование и регистр имени. Это не проверка диска клиента.
- `SEARCH_PATH`: пути `GAME`, возвращённые API сервера (до 64). Наличие папки на диске само по себе не означает, что игра её использует.
- `PLACEMENT_SELECT`, `PLACEMENT_PING`, `PLACEMENT_GEOMETRY`, `PLACEMENT_TRANSFORM`: выбранный материал, координаты пинга, углы взгляда, смещение, ветка стены/пола, итоговая позиция и углы. Алгоритм использует **углы взгляда, а не нормаль поверхности**; диагностика его не меняет.
- `SPAWN_BEGIN`, `SPAWN_RESULT`, `SPAWN_NEXT_UPDATE`: попытка создания `env_decal`, индекс, существование сразу после спавна и на следующем обновлении мира, фактическая позиция/углы, ширина/высота/глубина, `ProjectOnWorld`, режим отрисовки, валидность material handle.
- `DB_INIT`, `DB_READY`, `DB_INSERT`, `DB_UPDATE`, `PLACEMENT_SAVE_RESULT`: инициализация, результат сохранения и присвоенный ID. `DB_*_ERROR` дополняются обычным error-логом. Учётные данные подключения в диагностический отчёт не включаются.
- `RECORD`, `ENTITY_SNAPSHOT`: сохранённые параметры и текущая сущность. Нет записи — возможен другой ID/карта или незавершённая/неудачная загрузка БД. Отчёт читает текущую память плагина, не делает свежий SQL-запрос.
- `TRANSMIT`: слот игрока, разрешение, настройка скрытия, принудительный показ, рассчитанная видимость и текущий серверный флаг передачи. Автоматически пишется только при `DebugPlayerTransmit=true`; в ручном отчёте — всегда для выбранных игроков.
- `ROUND_RESPAWN`, `ROUND_RECORD`: повторное создание после начала раунда.
- `EDIT_REQUEST`, `EDIT_RESULT`: изменение параметров через Panorama и результат сохранения. Для WASD изменения также видны в `DB_SAVE_BEGIN`/`DB_UPDATE`.

## Ограничения

Успешный `FileExists`, валидный handle или `serverTransmitFlag=True` **не доказывают**, что игрок отрисовал декаль. Плагин не анализирует содержимое `.vmat_c`, его зависимости `.vtex_c`, совместимость шейдера или прозрачность. Он также не может этим серверным отчётом проверить клиентское монтирование. Если серверная цепочка исправна, следующий шаг — ошибки материалов в консоли клиента и проверка самого материала/его зависимостей.

Workshop не является единственным способом установки: для локальной проверки допустима ручная установка в реально используемые игрой пути. Важно, чтобы нужные скомпилированные ресурсы и зависимости были доступны стороне, которая их загружает. Этот плагин не скачивает пользовательские ресурсы клиентам автоматически.

Лог содержит UTC-время, последовательный номер, поток, карту, поколение загрузки, пути сервера, имена/ID декалей и координаты; SteamID, IP и имена игроков намеренно не выводятся. Перед публичной отправкой просмотрите файл на наличие приватных путей/названий. Ротация: примерно 5 МиБ на файл и два архива `.1`/`.2` (возможен небольшой выход за лимит на одну строку).

Локально проверены компиляция, тесты логики/SQLite/ротации и XML/CSS-контракт. Работа на живом сервере CS2 и клиентская отрисовка требуют проверки на сервере.
